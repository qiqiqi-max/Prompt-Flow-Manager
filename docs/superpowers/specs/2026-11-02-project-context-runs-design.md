# 项目上下文档案与工作流独立运行记录

状态：方案 2 与本设计已由小主确认（2026-11-03）；进入实现。

## 目的与范围

让一套本地提示词和工作流能够用于多个项目，减少重复填写，同时避免项目之间的填充值与执行进度串用。

已确认的范围：项目上下文档案、工作流独立运行记录；采用独立本地数据文件，保持现有 Electron、原生 HTML/CSS/JS 与 Markdown 内容库。

下文未在对话中明确指定的字段、容量、迁移和交互细节均为实现方建议，随本设计一起提交确认，不视为小主已逐项同意。

### 非目标

- 不接入 AI 服务，不自动执行外部命令，不读取或扫描用户填写的项目路径。
- 不实现工作流图形编排、智能集合、选择性分享包、效果评分。
- 保留“复制成功后自动完成本步并推进”；不增加人工完成确认或结果附件。
- 不引入数据库或新的运行时依赖，不改写用户 Markdown 的 flow 结构。
- 不做自动项目检测、云同步或无上限历史保留。

## Approaches：落地方式

1. 扩展 config.json：开发改动较小，但整份配置在窗口与标签状态保存时频繁序列化，不适合承载逐渐增长的运行历史。
2. 独立 projects.json 与 workflow-runs.json：业务存储和窗口配置分离，主进程维护安全、原子写入及并发边界，补齐迁移和完整备份。小主选择此方案。

选方案 2 的代价是增加两个存储模块与对应的备份、IPC 和端到端测试；不以仅新增界面而遗漏持久化交付。

## 当前实现与接入点

- src/renderer.js 的 fillMemory 按占位符原文记忆，目前不区分项目；工作流的 values 优先于全局记忆。
- src/flow-run.js 是纯状态机，处理分支、汇合、跳过、回退和按最新图修复。保留并复用这些规则。
- config.flowRuns 目前按工作流相对路径保存一份进度，重新开始会覆盖这份进度。
- 主进程 rename/trash 与渲染进程 migrateFlowRun 均处理旧进度跟随，必须同时迁移至新接口，不能留下防抖写回旧数据的入口。
- 快速搜索面板只读取填充记忆，不独立写入，以免双窗口相互覆盖。
- 完整 ZIP 备份通过白名单读取、SHA-256 清单、导入独占闸门与快照回滚保证安全；新增业务文件必须纳入同一套流程。
- CODE_ROOT 负责代码，DATA_ROOT 负责用户数据；只读 CLI/MCP 暂不增加写接口或项目私有数据展示。

## 项目档案

### 数据与操作

DATA_ROOT/projects.json 使用 schema: 1，记录 activeProjectId 与项目数组。每个项目含：

- id：主进程生成的不透明稳定 ID，不由名称或路径派生。
- name、description、stack、path、constraints：名称必填，其余可选的普通文本。
- values：本项目的占位符填充记忆，键沿用现有 token 原文。
- createdAt、updatedAt、revision：主进程维护，revision 用于拒绝过期修改。

支持新建、编辑、切换、复制、删除档案。重名允许，列表以辅助描述/ID 区分，不以名称合并。复制生成新 ID，并复制字段和填充记忆，不复制运行历史。

删除前确认。删除有绑定运行的项目时拒绝，提示先将这些运行解除项目绑定；禁止顺带静默删除运行。解除绑定保留运行自己的上下文快照与 values。

默认有“未选择项目”状态，不自动把已有全局记忆归到某个项目。项目路径只是上下文文本，不授予任何文件系统操作能力。

### 填充规则

识别固定字段标签：项目名称/Project name、项目描述/Project description、技术栈/Tech stack、项目路径/Project path、项目约束/Project constraints；按解析后的字段标签匹配，不对子串或任意正文猜测替换。

主界面填写面板与快速搜索面板采用同一套纯函数规则：

1. 本次填写中用户实际输入的值。
2. 正在执行的独立运行自己的 values 与创建时的 contextSnapshot；projectId 为空时，快照只含当时全局 fillMemory，不含当前选中项目字段。
3. 非工作流复制时：所选项目的 values 优先于对应固定档案字段。
4. 未选择项目时：现有全局 fillMemory。
5. 模板默认值，然后为空。

选择了项目或执行绑定项目的运行时，不回落全局 fillMemory，避免串项目。没有固定标签匹配的 token 仍可手动填写并记入对应项目/运行。

用户清空预填值仍保持当前“留空原样保留”的行为，不在复制时偷偷补回值。复制原文不记忆新值。

普通复制成功后：有项目则只更新该项目记忆；无项目则沿用全局记忆。工作流复制更新该运行 values，不把运行中覆盖值写回项目档案。快速面板继续只读，不增加写权限。

装配器打开时可以从当前档案预填名称、描述；技术栈只对已有受支持的选项做明确映射，未知自由文本不自动勾选。编辑档案与临时修改装配内容互不覆盖，档案保存是显式操作。

## 独立运行记录

### 数据

DATA_ROOT/workflow-runs.json 使用 schema: 1，含 runs 数组、selectedByWorkflow 选择映射及 legacyImported 标志。

每次运行含：id、workflowRel、name、projectId（可为空）、contextSnapshot、originGraphSnapshot、graphSnapshot、progress、revision、createdAt、updatedAt、completedAt（可为空）、availability。

- contextSnapshot 是创建运行时的档案字段与填充记忆副本，固定这次运行的项目语境。
- originGraphSnapshot 保存创建时的图，不随后续编辑改变；graphSnapshot 保存最近一次已确认继续执行所使用的图。二者仅保存步骤 id、prompt、label、next；不复制提示词正文或版本，不声称可以重放旧正文。
- progress 复用 FLOW_RUN 的 current/done/skipped/history/values 形状。
- availability 区分可执行与工作流缺失/移出目录；是否完成按保存的图与进度计算。
- selectedByWorkflow 仅指向已存在且属于该工作流的运行；跨项目可同时存在多份运行。

历史记录不是不可变归档：用户明确选择后仍可继续或回退；结束日期随恢复执行清空。新建运行不会改动旧记录，“重新开始”改为创建新运行。

### 生命周期

打开流程后可选择该流程的运行、新建命名运行，默认选择最近一次选中的记录。新运行默认绑定当前项目，但创建时允许选择无项目或其他项目。

执行时始终使用运行绑定的上下文快照，不随全局项目选择改变。无项目运行同样固定使用创建时的全局 fillMemory 快照，不动态读全局记忆或当前选中项目。若需不同项目、更新后的档案或全局记忆，创建新运行；第一版不增加隐式同步快照操作。

复制、跳过、回退和分支选择由主进程基于最新工作流与持久化进度结算；渲染进程只发送单条操作和期望 revision，禁止上传整份历史覆盖。

切换文件、项目或运行、重新开始以及外部流程更新均使旧复制请求失效；复制完成后的推进再次校验 run ID、revision 和流程内容版本。操作期间保持当前运行的控件忙碌，避免同一次点击重复结算。

剪贴板与磁盘不能组成原子事务：复制成功但进度写盘失败时显示“已复制，进度未保存”，保留原进度，允许重试，不声称步骤已持久化完成。

工作流改名/移动到 workflows 内：所有运行和选择键一起迁移。删除或移出 workflows：保留历史但标为不可执行，移除活跃选择，不自动创建文件。以后同路径文件出现不自动认作原流程；用户明确选择恢复后按当前图校验。

工作流被修改时：提示有变化，用户确认继续后将 graphSnapshot 更新为最新图，并在同一次持久化操作中修复 progress、清除已不存在步骤的状态、重新计算 completedAt。originGraphSnapshot 不变；历史默认展示最近使用图，可说明与创建时不同，不承诺不可变审计历史或旧版提示词正文。仅查看历史不修复进度或改变完成状态。

删除运行需确认，仅删除明确选中的记录；如果是当前选中记录，选择同流程最近记录或回到未执行状态。

## 容量与异常保护（实现方建议）

- 最多 100 个项目、1000 次运行；达到上限时拒绝新增并提示整理，不自动淘汰未完成或历史记录。
- 项目名称/运行名称最长 200 字符；描述、技术栈、路径和约束各最多 20000 字符。
- 延用占位符限制：最多 200 个值，单值不超过 20000 字符；过长值不截断后预填，输入时提示。
- 单次运行最多 500 个步骤；projects.json 与 workflow-runs.json 各不超过 16 MiB。新增/修改前验证编码后大小，读取时先 stat 限制；完整备份对这两个明确条目允许同等上限，包累计仍不超过 64 MiB。
- ID、字段类型、相对路径、长度、revision 全部由主进程校验；危险属性不写入业务对象。业务文件拒绝 symlink/junction，不接受渲染传来的存储文件路径。
- 原子写入完成前不提交缓存或返回成功；无法读取（除 ENOENT 外）不当成空库；损坏文件先保留 .corrupt 留档，界面显示恢复提示，无法留档则拒绝覆盖。
- 未知较新 schema 只读报错，不降级为空并覆盖。

## 并发、锁和 IPC

两个存储模块不 require electron，文件路径、原子写函数、错误工厂与 fs 依赖可注入，以裸 Node 测试。

主进程负责业务操作，并向主窗口推送最小变更通知。页面重读必要快照，不包含任意磁盘路径能力。

采用一个 workspace 队列串行项目、运行与二者关系修改；复用写入闸门。普通多 key 操作必须在不持有 shared 的情况下，一次性预留全部 key 的链尾，等待所有前序任务结束后才进入 shared，并在一个 finally 中释放全部预留。不能先进入 ver:* 的 shared，再等待 workspace/config 的链尾；否则后者可能已排在 exclusive 后，形成互等。新业务触达的 rename/trash/迁移均走此统一外层入口，内部 Locked 方法不重复预约 key 或进入 shared。导入则先独占闸门，并直接调用 Locked 方法，不等待可能排在本次 exclusive 后的普通写队列。

文件改名/删除与 workspace 更新采用明确固定的 key 分类顺序：ver:* → trash（需要时）→ workspace → config（仅迁移需要时）。预留动作同步登记全部相关 key，不在已持有 shared 的任务内追加等待其他 key。新增锁序/闸门对照检查；新运行/步骤结算只读流程文件，并校验读到的版本。若处理外部改动需要另一组 key，结束当前任务后提交新任务，不嵌套取锁。

保留现有其他存储的锁纪律；不在本功能中顺手重构无关写队列。文件变更与业务索引的多文件写入使用快照与回滚，失败不得返回完全成功，回滚失败需列出保留路径并提示恢复。

建议 IPC 分组：读取/创建/更新/选择/复制/删除项目；读取/创建/选择/结算/解除绑定/删除运行；主进程变更通知。名称由实现者定，但参数为字段白名单或 ID，不提供写任意 JSON 的接口。

所有修改带期望 revision，过期请求拒绝并刷新，不以最后写入者覆盖其他修改。快速面板呼出时取当前档案最新只读快照；主窗口删除/切换项目后旧面板填充上下文失效并重读。

## 旧数据迁移

启动业务存储前，在 workspace 锁内执行一次幂等迁移：

1. 读取现有 config.flowRuns；只认合法工作流键和 FLOW_RUN.restore 可恢复的记录。
2. 每个旧工作流生成一个未绑定项目的运行，使用确定的 legacy ID 去重，保留进度与填写值，读取工作流生成图快照；迁移时全局 fillMemory 作为该运行 contextSnapshot，后续不动态变化。
3. 旧键对应文件不存在时也保留原始进度为不可执行记录，不静默丢弃；没有图时不能标为已完成。
4. 原子保存新运行文件及 legacyImported 标志后才启用新接口；失败保留旧配置并允许下次重试，禁止写出一半后标迁移完成。
5. config.flowRuns 原样留作只读迁移备份，不再被正常页面更新，不为兼容回写最新运行。文档明确旧版应用回退不支持同步新运行。

全局 fillMemory 不清空，也不自动复制到项目。迁移的无项目运行使用迁移时全局记忆快照作为补充，旧运行 values 优先；有项目的运行严格隔离。所有运行均不受 activeProjectId 后续切换影响。

## 完整备份与导入

在完整 ZIP 中增加 .pfm/projects.json、.pfm/workflow-runs.json 两个精确白名单条目，纳入 SHA-256 清单与导入预览，其他 JSON 路径继续拒绝。

导出在短时独占闸门内获取全部内容和业务数据一致快照，释放后压缩/写出，不能边读正文边接受运行变更而生成混合状态。不得在持有闸门时等待系统对话框。

导入支持旧备份缺少新条目；有新条目时严格校验 schema/大小/数据，不把损坏业务数据当空库。先导入正文得到 restoredRels，再恢复档案与运行：

- 导入档案/运行生成新 ID，避免覆盖本机数据；同名保留两份。所有项目 ID、选择键和运行引用按映射重建。
- workflowRel 和 graphSnapshot 中的 prompt 路径只使用已导入文件映射；有未包含文件的引用时保留原文本并标为不可执行/引用待确认，不自动绑定本机同名文件。
- 映射必须同时作用于导入后实际执行读取的工作流副本，不能只修改运行的图快照。内容导入完成、restoredRels 完整后，仅对本次新建副本的 flow.prompt 和 include 指令做精确结构化路径重写；普通正文/标签/未知 frontmatter 不改，不改本机既有文件，也不整体重序列化 flow。两种图快照同步映射。模板/提示词副本中的嵌套 include 同样映射，防止流程读到了正确副本但片段仍来自本机旧文件。清单校验基于包内原始字节，在校验成功后转换；转换纳入导入事务，版本说明的当前正文哈希按转换后的正文重建。
- 执行前校验本次导入运行的全部 prompt/include 依赖；依赖没有导入映射时保持不可执行，并明确显示待确认路径。第一版不新增任意本机依赖绑定能力，重新创建经过用户整理的流程运行才解除该限制。
- 保留本机当前项目和运行选择，不因导入切换；导入快照中的机器路径作为普通文本保留，并在预览中提示可能需要修改。
- 预检容量，超限整次导入拒绝，不部分丢弃历史后返回成功。
- 两个业务文件纳入 createImportTransaction 快照；任一后续步骤失败一起回滚，回滚后丢弃缓存并推送刷新。
- 原有主题、窗口、收藏/使用统计的迁移策略保持不变。

明确告知：完整备份包含档案路径、约束及填充值，分享前需要检查；不自动上传这些内容。诊断导出仅包含业务条数/状态，不包含档案字段、运行值和名称。

## 验证与交付

先写会失败的测试，再实现；所有新增/修改断言按 CONTRIBUTING.md 做逐条反向对照，证明指定目标断言会红。

纯模块测试：schema/大小/危险键、项目 CRUD/隔离/清空/默认值、独立运行/快照/回退/历史、revision、幂等迁移、并发关系约束、写失败保留旧文件、锁序与导入无死锁。

真实 Electron 测试：两项目同 token 不串值；快速面板与主窗口一致；装配器预填；同流程两运行交替续跑和两次启动恢复；旧迁移；过期复制不推进；复制后写失败提示；改名/删除/外部改动；项目解除绑定；完整备份往返及业务文件阶段故障回滚。

保留当前流程图/复制/批量操作测试，更新旧 config.flowRuns 的预期为新接口行为。补中英文文案、键盘与焦点回归、800×500/字号缩放检查。

交付前跑 lint、test:all、dist、test:packaged；严格沙箱以支持的环境/CI 结果为准，不把本机降级通过说成严格沙箱通过。

文档同步 README、CHANGELOG、CLAUDE.md/CONTRIBUTING.md 的格式与测试清单。中文分项提交，分支 + PR，不直接推 main；GitHub 推送/合并按届时有效授权执行，不自动覆盖旧发布资产。
