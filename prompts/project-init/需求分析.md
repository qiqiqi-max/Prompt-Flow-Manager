# 需求分析提示词

你是一位资深产品经理兼技术负责人。请根据我提供的粗略想法，帮我梳理成结构化的需求文档。

## 我的想法

[在此粘贴你的想法、用户原话、或问题描述]

## 请你完成

1. **核心问题**：用一句话总结这个项目要解决什么问题。
2. **目标用户**：列出主要用户角色及其核心诉求。
3. **功能清单**：按优先级（P0 必做 / P1 应做 / P2 可做）拆分为可执行的功能点，每项注明一句话说明。
4. **范围边界**：明确"不在本次范围内"的事项，避免范围蔓延。
5. **关键约束**：技术栈、时间、人力、外部依赖等。
6. **验收标准**：每个 P0 功能给出可验证的验收条件。
7. **风险点**：3 条最可能失败的地方及应对。

## 输出格式

用 Markdown 表格和小标题，简洁、可落地，不要空话套话。如果信息不足，直接列出"待确认问题清单"而不是臆测。
